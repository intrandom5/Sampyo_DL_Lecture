### [슬라이드 3] 왜 Auto ML인가 — 모델 선택의 어려움

- **기존 방식의 문제**
  - 머신러닝 모델 종류가 수십 가지 (선형 회귀, 랜덤 포레스트, XGBoost, LightGBM ...)
  - 각 모델마다 하이퍼파라미터가 다르고 조합이 수백 가지
  - "어떤 모델이 이 데이터에 맞는가"를 알려면 직접 다 돌려봐야 함
  - 숙련된 데이터 사이언티스트도 며칠이 걸리는 작업

- **Auto ML의 해답**
  - 여러 모델을 자동으로 학습·비교·정렬해주는 도구
  - 사람이 할 일: 데이터 넣기 + 결과 해석
  - 모델이 할 일: 나머지 전부

- **오늘 사용할 도구: PyCaret**
  - 3줄 코드로 10+ 모델 자동 비교
  - Scikit-learn 위에 빌드 → Day 1 선이수 내용과 연속성
  - 교육 후 부서에서도 무료 사용 가능 (오픈소스)

### [슬라이드 4] PyCaret이란 무엇인가

- **PyCaret = 머신러닝 파이프라인 자동화 라이브러리**
  - setup → compare_models → 끝 (핵심 흐름)
  - 전처리(결측치·정규화·인코딩), 학습, 평가, 시각화를 한 번에 처리

- **직관적 비유**
  - 일반 머신러닝: 요리사가 재료 손질부터 조리까지 직접 하는 것
  - PyCaret: 재료(데이터)만 넣으면 여러 셰프(모델)가 동시에 요리해서 결과를 줄 판

- **PyCaret이 비교하는 주요 모델들 (회귀)**
  - Extra Trees Regressor
  - Gradient Boosting Regressor
  - XGBoost Regressor
  - LightGBM
  - Random Forest
  - CatBoost
  - Decision Tree
  - Linear Regression
  - ... 등 10개 이상 자동 비교

### [슬라이드 5] 모델 성능 지표 읽는 법

- **먼저 콘크리트 압축강도를 다시 짚고 가기**
  - 콘크리트를 만들고 28일 후에 눌러서 얼마나 버티는지 측정한 값 (단위: MPa)
  - 숫자가 클수록 더 단단한 콘크리트
  - 이 데이터에 수치가 다양한 이유: 배합 비율(물·시멘트·골재 등)을 다양하게 바꿔가며 실험한 것

- **회귀 문제에서 쓰는 지표 3가지**

| 지표 | 한 줄 의미 | 좋은 값 |
|---|---|---|
| R² (결정계수) | "모델이 데이터를 얼마나 잘 설명하는가" — 100점 만점에 몇 점짜리 모델인가 | 1에 가까울수록 좋음 |
| RMSE | 모델이 예측할 때 평균적으로 몇 MPa 틀리는가 | 작을수록 좋음 |
| MAE | RMSE와 비슷하지만 크게 틀린 경우에 덜 민감한 오차 | 작을수록 좋음 |

- **"이 모델이 쓸만한가"를 판단하는 방법**
  - RMSE 3.84 MPa → 모델이 평균적으로 3.84 MPa씩 틀린다는 뜻
  - 이게 크냐 작냐를 판단하려면 기준이 필요함
  - **기준 잡는 법**: 현장에서 가장 중요한 판단 기준값과 비교
    - KS 표준에서 1종 시멘트 콘크리트는 28일 강도가 **42.5 MPa 이상**이어야 합격
    - 즉, 42.5 근처에서 ±3.84 MPa가 현장 판단에 허용 가능한 오차인지를 담당자가 결정
    - "우리는 ±5 MPa 감수하고 배합 조정한다" → 이 모델 쓸 수 있음
    - "±2 MPa 이내여야 한다" → 모델 더 개선 필요
  - 👉 **모델 성능의 기준은 숫자가 아니라 현장 요구사항에서 나온다**

- **주의할 점**
  - 가장 높은 R² 모델이 항상 최선은 아님
  - 학습 시간, 해석 가능성, 실제 배포 용이성도 함께 고려해야 함

### [슬라이드 6] PyCaret compare_models 결과 읽기

- **PyCaret Top 8 결과표 예시 (UCI Concrete 기준)**

| 모델 | R² | RMSE | MAE | 학습 시간 |
|---|---|---|---|---|
| ⭐ Extra Trees Regressor | 0.927 | 3.84 | 2.91 | 0.42s |
| Gradient Boosting | 0.918 | 4.02 | 3.05 | 1.18s |
| XGBoost Regressor | 0.912 | 4.18 | 3.12 | 0.88s |
| LightGBM | 0.908 | 4.25 | 3.21 | 0.31s |
| Random Forest | 0.901 | 4.41 | 3.34 | 0.96s |

- **어떤 모델을 선택할 것인가?**

  - 속도 우선: LightGBM (R² 큰 차이 없으면서 가장 빠름)
  - 해석 용이성 우선: 선형 회귀 (R²는 낮지만 비전문가도 이해 가능)
  - 👉 "정답은 없다 — 어떤 목적으로 쓸 모델인가"에 따라 선택

## 🔷 세션 2 (13-15) : 모델 해석 + 성능 개선

### [슬라이드 8] 블랙박스 문제 : 모델이 왜 그런 예측을 했는가

- **트리 기반 모델의 딜레마**
  - Extra Trees, XGBoost, LightGBM → 정확하지만 왜 그런 예측을 했는지 사람이 이해하기 어려움
  - 현장에서 문제가 되는 순간: "이 배합으로 만들면 38 MPa라고 하는데, 왜요?"
  - 담당자가 설명 못 하면 → AI 결과를 신뢰하지 않고 사용하지 않음

- **PyCaret의 해답: `interpret_model()` 함수**
  - 한 줄 코드로 변수 중요도 시각화 자동 생성
  - "어떤 변수가 이 예측에 얼마나 기여했는가"를 그래프로 보여줌
  - 모델을 믿을 수 있는 근거를 만들어줌
  - 품질 이상 발생 시 원인 변수 추적 가능

---

### [슬라이드 9] 변수 중요도 그래프 읽는 법

- **그래프 구조**
  - y축: 변수 이름 (영향도 높은 순서로 정렬)
  - x축: 각 변수의 영향력 크기 (양수 = 강도 증가에 기여, 음수 = 강도 감소에 기여)
  - 점의 색: 해당 변수의 실제 값 (빨강 = 높음, 파랑 = 낮음)

- **UCI Concrete 결과 해석 예시**

| 변수 | 그래프 해석 | 현장 의미 |
|---|---|---|
| Age (양생 기간) | 가장 큰 양의 영향 | 오래 양생할수록 강도 크게 증가 |
| Cement (시멘트량) | 두 번째로 큰 양의 영향 | 시멘트 많을수록 강도 증가 |
| Water (물) | 가장 큰 음의 영향 | 물 많을수록 강도 감소 |
| Superplasticizer | 중간 수준 양의 영향 | 감수제 적절히 쓰면 강도 증가 |

- **현장에서 의미 있는 질문으로 연결**
  - "양생 기간을 7일 더 늘리면 강도가 얼마나 달라지나?"
  - "물-시멘트 비율을 낮추면 어떤 효과가 있나?"
  - 👉 AI가 숫자만 주는 게 아니라 **배합 설계 판단 근거**를 제공

---

### [슬라이드 10] 모델 성능 개선 : 하이퍼파라미터 튜닝

- **하이퍼파라미터란?**
  - 모델이 학습으로 찾는 값이 아니라, **사람이 미리 설정해야 하는 값**
  - 예) 트리의 깊이, 학습률, 반복 횟수 등
  - 이 값을 어떻게 설정하느냐에 따라 모델 성능이 달라짐

- **PyCaret의 해답: `tune_model()` 함수**
  - 한 줄 코드로 최적 하이퍼파라미터를 자동으로 탐색
  - 수백 가지 조합을 자동으로 시도해서 가장 좋은 조합을 찾아줌
  - 튜닝 전후 R²·RMSE 비교 → 성능 개선 확인

- **직관적 비유**
  - 튜닝 없이: 새 카메라를 사서 기본 설정 그대로 쓰는 것
  - 튜닝 후: 촬영 환경에 맞게 조리개·셔터스피드를 최적으로 조정한 것
  - 같은 카메라(모델)인데 결과물(성능)이 달라짐

### [슬라이드 14] Gradio란 무엇인가

- **Gradio = 머신러닝 모델을 웹 인터페이스로 감싸주는 라이브러리**
  - 입력창(슬라이더, 숫자 입력)과 출력창을 자동으로 생성
  - 모델과 사용자 사이의 **번역기** 역할
  - 사람이 이해하는 입력 → 모델이 이해하는 형식 / 모델 출력 → 사람이 읽는 형식

- **작동 흐름**
  ```
  사용자가 배합값 입력 (Cement, Water, Age 등)
              ↓
  Gradio가 입력값을 모델에 전달
              ↓
  PyCaret 모델이 압축강도 예측
              ↓
  Gradio가 결과를 화면에 표시
  ```
