## 🔷 세션 1 (09-12) : 시계열 전처리

### [슬라이드 2] 진동 신호란 무엇인가

- 공장 회전기계(베어링)에 부착된 진동 센서가 측정하는 것
- x축 = 시간, y축 = 진동의 세기(진폭)
- **정상 베어링 vs 손상 베어링의 파형 차이**
  - 정상: 규칙적이고 잔잔한 파형
  - 손상: 특정 구간에서 튀는 충격 파형 반복
- 👉 이 차이를 AI가 학습하게 만드는 것이 목표

### [슬라이드 3] CWRU Bearing 데이터셋이란

- Case Western Reserve University(미국)에서 공개한 베어링 진동 벤치마크 데이터셋
- 머신러닝/딥러닝 베어링 고장 진단 연구의 표준 데이터셋으로 전 세계적으로 사용
- **실험 구성**
  - 2HP 인덕션 모터 + 토크 센서 + 다이나모미터 구성의 테스트 리그
  - 베어링에 EDM(방전가공)으로 인위적 결함 생성: 결함 크기 7~40mil
  - 모터 부하: 0~3HP / 회전 속도: 1720~1797 RPM
- **센서 위치 3곳**
  - **DE (Drive End)**: 모터 구동 쪽 베어링 — 주로 사용되는 신호
  - **FE (Fan End)**: 모터 팬 쪽 베어링
  - **BA (Base)**: 모터 베이스 플레이트
- **샘플링 레이트**
  - DE 데이터: 12kHz 및 48kHz 두 가지로 수집 (1초에 각각 12,000번 / 48,000번 측정)
  - FE 데이터: 12kHz로만 수집
- **파일 형식**: MATLAB `.mat` 형식, 파일 하나당 약 120,000~240,000개 샘플 (약 10초 분량)
- **4가지 클래스 레이블**
  - Normal (정상)
  - Inner Race 손상 (내륜)
  - Outer Race 손상 (외륜)
  - Ball 손상 (볼)

### [슬라이드 4] 시계열 데이터의 특성

- 일반 표 데이터와 다른 점: **순서가 의미를 가진다**
  - 예) "9시 0분 0초 진동값 → 9시 0분 0.001초 → ..." 이 순서를 바꾸면 의미 없음
- 12kHz 기준으로 1개 `.mat` 파일 안에 약 12만~24만 개의 측정값이 1열로 나열됨
  ```
  [0.0023, -0.0041, 0.0089, -0.0012, 0.0156, ...]  # 길이 ~120,000
  ```
- 이 긴 신호를 그대로 모델에 넣을 수 없음 → 윈도우 슬라이싱 필요

---

### [슬라이드 5] 윈도우 슬라이싱 : 긴 신호를 고정 크기로 자르기

- **왜 잘라야 하는가?**
  - 딥러닝 모델은 고정된 크기의 입력만 받을 수 있음
  - 원본 진동 신호는 수십만 개짜리 가변 길이 → 통째로 넣는 것 자체가 불가능
  - 모델이 처리할 수 있는 고정 크기로 잘라서 입력해야 함
- **슬라이딩 윈도우 개념**
  - 창문 크기(window size): 한 번에 몇 개의 측정값을 볼 것인가
  - stride: 창문을 몇 칸씩 밀 것인가
- 예시 (그림으로 표현 권장)
  ```
  [■■■■■□□□□□□□□□□]  ← 첫 번째 샘플
  [□■■■■■□□□□□□□□□]  ← 두 번째 샘플 (stride=1)
  [□□■■■■■□□□□□□□□]  ← 세 번째 샘플
  ```
- ⚠️ **윈도우 크기 선택의 트레이드오프**
  - 너무 짧으면: 창문 안에 패턴이 다 안 들어와서 분류 성능 저하
  - 너무 길면: 모델 입력이 커져서 연산 부담 증가
  - 창문 밖 정보는 모델이 볼 수 없다는 점은 구조적 한계로 인지할 것

---

### [슬라이드 6] FFT : 진동 신호를 주파수로 바라보기

- **직관적 비유**
  - 피아노 화음을 들었을 때, "도+미+솔이 섞여 있다"고 분해하는 것
  - 복잡한 진동 파형에서 "어떤 주파수 성분이 강한가"를 뽑아냄
- 시간 도메인 → 주파수 도메인 변환
  - 시간 도메인: 언제 얼마나 흔들렸는가
  - 주파수 도메인: 어떤 주기의 진동이 얼마나 강한가
- 왜 필요한가?
  - 베어링 손상 부위마다 특정 주파수에서 뾰족한 피크 발생
  - Inner Race / Outer Race / Ball 각각 다른 주파수 패턴
  - FFT 결과만으로도 전문가가 손상 유형을 육안 식별 가능한 경우 있음
- ⚠️ FFT만으로 충분하지 않은 경우
  - 노이즈에 피크가 묻혀 있거나, 복합 손상(외륜 + 볼 동시 손상)일 때
  - 전문가 없이 자동 판단이 필요할 때
  - 👉 이런 경우를 위해 딥러닝이 필요
- 👉 수식 없이 그래프 비교로 설명 (정상 vs 손상 FFT 스펙트럼 그림 활용)

---

### [슬라이드 7] 전처리 흐름 : CWRU 데이터에 실제로 적용하면

- **원본 신호 (DE 채널, 12kHz)**
  ```
  signal = [0.0023, -0.0041, 0.0089, ...]  # 길이 약 120,000 (약 10초)
  ```

- **① 윈도우 슬라이싱** (window_size=2048, step=1024)
  ```
  sliding_window(signal)
  → shape: (약 115개 세그먼트, 2048)
  # 2048 샘플 = 12kHz 기준 약 0.17초 분량
  ```

- **② FFT 적용** (세그먼트 하나씩)
  ```
  compute_fft(segment)  # 세그먼트 1개 입력
  → fft_vals shape: (1025,)
  # 2048 샘플 → rfft → 대칭 절반 사용 → 2048//2 + 1 = 1025개 주파수 성분
  ```
  - 전체 세그먼트에 적용하면: `(115, 1025)` — 115개 샘플, 각각 1025개 주파수 특징

- **③ 정규화**
  ```
  (115, 1025) 배열의 값을 학습 데이터 기준으로 스케일 통일
  ```

- **④ 모델 입력**
  ```
  1D-CNN 입력: (batch_size, 1025)  # 고정 크기 확보
  ```

- 👉 윈도우 크기를 고정하면 → FFT 출력 크기 고정 → 모델 입력 크기 자동으로 고정

---

### [슬라이드 8] 정규화 : 모델이 공정하게 학습하도록

- 왜 필요한가?
  - 센서마다 측정 단위와 수치 범위가 다를 수 있음
  - 딥러닝 모델은 숫자의 크기 차이에 민감하게 반응
  - 입력값 범위를 통일해줘야 학습이 안정적으로 진행됨
- 두 가지 방법
  - **Min-Max 정규화**: 모든 값을 0~1 사이로 변환
  - **StandardScaler**: 평균 0, 표준편차 1로 변환
- ⚠️ 시계열 데이터에서 주의할 점
  - 정규화 기준(평균, 최대값 등)은 반드시 학습 데이터에서만 계산
  - 미래 데이터 정보가 학습에 새어 들어가면 안 됨 (Data Leakage)

## 🔷 세션 2 (13-15) : 1D-CNN 학습

### [슬라이드 10] CNN이란 무엇인가

- **CNN (Convolutional Neural Network, 합성곱 신경망)**
  - 딥러닝 모델의 한 종류
  - 핵심 능력: **데이터 안에서 패턴을 자동으로 찾아내는 것**
- 가장 유명한 사용처는 이미지 인식
  - 수천 장의 고양이 사진을 학습 → "이런 패턴이 있으면 고양이"를 스스로 학습
  - 사람이 "귀가 뾰족하면 고양이"라고 규칙을 직접 짜지 않아도 됨
- **그런데 패턴을 찾는 능력 자체는 이미지에만 쓸 수 있는 게 아님**
  - 이미지: 가로×세로 2차원 공간에서 패턴 탐지
  - 진동 신호: 시간 축 1차원 위에서 패턴 탐지 → **1D-CNN**
  - 구조의 원리는 같고, 적용하는 데이터 차원만 다름
- 베어링 진동에 적용하면
  - "이 시간 구간에 이런 충격 파형이 반복되면 → 외륜 손상"
  - 이 패턴을 사람이 정의하지 않아도 CNN이 데이터에서 스스로 학습

---

### [슬라이드 11] 1D-CNN 구조 직관

- **필터(커널)** = 특정 파형 패턴을 탐지하는 탐지기
  - 필터가 시간 축을 따라 슬라이딩하면서 패턴 일치 여부 확인
  - 필터 여러 개 = 여러 종류의 패턴을 동시에 탐지
- **Pooling** = 탐지 결과를 압축
  - 정확한 위치보다 "이런 패턴이 있었냐 없었냐"가 중요
  - 데이터 크기를 줄여 연산 효율화
- **Flatten → Fully Connected** = 최종 분류
  - 압축된 특징을 펼쳐서 4가지 클래스 중 하나로 판단

---

### [슬라이드 12] 4클래스 분류 구조

- 출력: Normal / Inner Race / Outer Race / Ball 중 하나
- Softmax: 각 클래스에 대한 확률값 출력
  - 예) Normal 2%, Inner Race 1%, **Outer Race 95%**, Ball 2%
- 손실 함수: Cross-Entropy Loss
  - 예측 확률이 정답 클래스에서 높을수록 손실이 낮아짐
  - 학습 = 이 손실을 줄이는 방향으로 가중치 업데이트

---

### [슬라이드 13] 결과 해석 : Accuracy와 Confusion Matrix

- **Accuracy 98%** = 100개 중 98개를 올바르게 분류
- **Confusion Matrix** = 어떤 클래스를 어떤 클래스로 헷갈렸는가
  - 단순한 정확도보다 훨씬 중요한 정보 포함

| 실제 \ 예측 | Normal | Inner | Outer | Ball |
|---|---|---|---|---|
| Normal | 99 | 0 | **1** | 0 |
| Outer Race | 0 | 0 | 100 | 0 |

- 현장에서 중요한 판단
  - **Outer Race를 Normal로 분류** = 고장을 놓침 → 매우 위험
  - Normal을 Outer Race로 분류 = 멀쩡한데 점검 → 비용 낭비이지만 안전
  - 👉 어떤 오류가 더 치명적인지를 기준으로 모델을 평가해야 함

## 🔷 세션 3 (15-18) : CNN-LSTM 고도화

### [슬라이드 15] 1D-CNN의 한계 : 시간 흐름을 모른다

- 1D-CNN이 보는 것: 창문 안의 순간 패턴
- 1D-CNN이 못 보는 것: 며칠에 걸친 변화 추세
- 실제 베어링 마모 시나리오
  - 처음에는 약한 이상 징후 → 점점 심해짐 → 최종 고장
  - 단일 시점 파형보다 **변화의 흐름**이 더 중요한 경우 존재
- 👉 이 흐름을 잡기 위해 LSTM을 추가

---

### [슬라이드 16] LSTM : 기억하는 네트워크

- LSTM (Long Short-Term Memory)
- 핵심 직관: **"중요한 것은 오래 기억하고, 불필요한 것은 지운다"**
- 두 가지 기억 통로
  - **Cell State**: 장기 기억 (중요한 정보 보존)
  - **Hidden State**: 단기 기억 (직전 상태 전달)
- 게이트 구조 (수식 없이 역할만)
  - 입력 게이트: 새 정보를 얼마나 받아들일지
  - 삭제 게이트: 기존 기억을 얼마나 지울지
  - 출력 게이트: 다음 단계에 얼마나 전달할지

---

### [슬라이드 17] CNN-LSTM 연결 구조

```
진동 신호 시퀀스 입력
        ↓
  [1D-CNN 블록]
  로컬 패턴 추출
  (특정 파형 패턴 탐지)
        ↓
  [LSTM 블록]
  시간적 맥락 학습
  (패턴의 변화 흐름 추적)
        ↓
  [Fully Connected]
  최종 고장 유형 분류
        ↓
  Normal / Inner / Outer / Ball
```

- CNN 역할: 각 시점의 특징 추출기
- LSTM 역할: 추출된 특징들의 시간 흐름 해석기

---

### [슬라이드 18] 시멘트 공장 실설비 적용 가능성

- **CWRU 기반 CNN 접근법이 시멘트 공장에서도 유효하다는 것이 연구로 검증됨**
  - Liang et al. (2024), Engineering Science and Technology, Elsevier
  - 중국 시멘트 공장 3개 설비에서 직접 진동 데이터 수집 후 CNN 모델 학습·검증

| 설비 | 고장 유형 | 진단 정확도 |
|---|---|---|
| 롤러 프레스 (B3G11B) | 내륜 결함 | 94.64% |
| 원심팬 (B3G20B) | 불균형 결함 | 97.62% |
| 메인 배기팬 (B3955B) | 외륜 결함 | 95.43% |

- ⚠️ **중요한 전제 조건**
  - CWRU 모델을 공장에 그대로 가져다 쓴 것이 아님
  - 공장 현장에서 **별도로 진동 데이터를 수집**해서 모델을 새로 학습시킨 것
  - 즉, CWRU는 "어떤 접근법으로 풀 수 있는지"를 알려주는 출발점
  - 실제 공장 적용을 위해서는 **현장 데이터 수집 → 재학습** 과정이 필요
