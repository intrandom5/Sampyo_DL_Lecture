# 실습 노트북 작성 가이드라인

이 문서는 `1. Data Preprocessing 실습.ipynb`처럼, **비개발자가 AI에게 지시해서 코드를 채우는 실습 노트북**을 만들 때 따르는 형식을 정리한 것이다. 이후 다른 노트북(Day2 이후 포함)을 만들 때도 이 가이드라인을 그대로 따른다.

## 1. 기본 철학

- 코드 셀은 **전부 빈 칸**으로 둔다. 직접 타이핑하지 않고, AI(ChatGPT, Copilot, Claude 등)에게 지시해서 채우는 것을 전제로 한다.
- 마크다운 셀에는 "무엇을 할지"와 "AI에게 어떻게 지시할지"에 필요한 정보만 담는다. 코드 자체나 구체적인 구현 절차는 적지 않는다.
- 원본(설명용) 노트북에 있던 **이해를 돕기 위한 시각화·비교 코드는 제외**한다. 실습 노트북은 핵심 처리 과정(전처리, 변환 등)에만 집중한다.
- 원본의 이론/도메인 설명(왜 이 작업이 필요한지, 트레이드오프, 주의사항 등)은 최대한 유지한다. 비개발자가 코드 없이도 "왜 이걸 하는지"를 이해할 수 있어야 한다.

## 2. 노트북 첫 셀: 사용법 안내

가장 처음에 아래 내용을 담은 markdown 셀을 둔다 (매 노트북 공통, 내용은 거의 동일하게 재사용 가능):

- 코드 셀이 비어있고 AI에게 지시해서 채워야 한다는 안내
- 각 코드 셀 위의 "🎯 실습 과제" 블록에 무엇이 담겨있는지 설명
- 좋은 프롬프트의 구성 요소(입력/처리/출력/확인) 또는 핵심 원칙
- "변수명을 마크다운에 적힌 그대로 사용해야 다음 단계에서 이어 쓸 수 있다"는 주의사항

## 3. 전체 구성: STEP 단위

- 노트북 전체를 **STEP 1, STEP 2, ...** 순서로 나눈다.
- 하나의 파이프라인을 다루는 경우, **"1개의 예시(파일/샘플)로 전체 과정을 끝까지 진행 → 마지막에 함수로 묶기 → 전체 데이터로 확장"** 순서를 기본으로 한다.
  - 예: STEP1~5(개념 단위 처리) → STEP6(함수로 묶기) → STEP7(전체 데이터에 적용 + 라벨링 + 합치기)
- 각 STEP은 보통 "설명(markdown) → 실습 과제(markdown) → 빈 코드 셀" 1세트로 구성한다. 한 STEP 안에 여러 개의 작은 작업이 있다면 "실습 과제 + 빈 코드 셀" 세트를 여러 번 반복할 수 있다.
- 마지막에는 전체 흐름을 표 + 다이어그램으로 정리하는 "전체 흐름 정리" 셀을 둔다.

## 4. STEP 설명(markdown) 작성 규칙

- `---` 구분선 + `## STEP N. 제목`으로 시작한다.
- 이 STEP에서 **왜** 이 작업이 필요한지, 어떤 개념인지를 비개발자 눈높이에서 설명한다.
  - 비유, 그림(ASCII 다이어그램), 표 등을 적극 활용한다.
  - 트레이드오프나 주의사항(⚠️)이 있다면 반드시 포함한다.
- 원본 노트북에 있던 "토이 예제로 손으로 먼저 해보기", "함수로 만들기 전 단계" 같은 **중간 학습용 단계는 생략**하고, 핵심 개념 설명 + 최종 실습 과제로 압축한다.

## 5. "🎯 실습 과제" 블록 작성 규칙

각 빈 코드 셀 바로 위에 아래 형식을 둔다.

```markdown
### 🎯 실습 과제

**목표**

(이 코드 셀에서 무엇을 만들어야 하는지, 1~3문장으로 설명)

**알아두면 좋은 용어**

- (이 작업과 관련된 개념/도메인 용어. 예: shape, 샘플링 레이트, FFT, 정규화, overlap, data leakage)
- ⚠️ 함수명/변수명은 여기에 적지 않는다. "알아두면 좋은 용어"는 AI에게 지시할 때 사용할 개념어다.

**입력 / 출력**

| | 이름 | 형태 |
|---|---|---|
| 입력 | `변수명` | 자료형/shape |
| 출력 | `변수명` | 자료형/shape |

**AI에게 줄 수 있는 프롬프트 예시**

> (입력과 출력의 형태(shape, 자료형)만 명시하는 한두 문장. 처리 과정의 세부 절차는 적지 않는다 — 그 부분은 사용자가 직접 생각해서 AI에게 지시하도록 남겨둔다.)
```

### 세부 원칙

- **목표**: "무엇을 만들어야 하는가"에 집중한다. 어떻게 만드는지(알고리즘, 반복문 구조 등)는 적지 않는다.
- **알아두면 좋은 용어**: 함수명·변수명이 아니라 **개념/도메인 용어**만 적는다 (shape, 샘플링 레이트, FFT, 정규화, fit/transform, overlap, data leakage, concatenate 등).
- **입력 / 출력 표**: 가장 중요한 부분. 이전 단계에서 만든 변수명과 형태(shape, dtype)를 입력으로, 이번 단계에서 만들어야 할 변수명과 형태를 출력으로 명시한다. **뒷 단계는 이 변수명을 그대로 가정**하므로, 이름이 바뀌면 전체 일관성이 깨진다.
- **AI 프롬프트 예시**: 입력/출력의 형태(shape, 자료형, 변수명)만 알려주는 수준으로 작성한다. "어떻게" 처리할지에 대한 구체적인 절차나 코드 구조는 적지 않는다 — 너무 구체적이면 그대로 복붙해서 끝나버리고, 사용자가 직접 고민할 여지가 없어진다.

## 6. 변수명/함수명 일관성

- STEP 사이에서 데이터가 이어지므로, 각 STEP의 "입력/출력 표"에 적은 변수명은 이후 STEP에서도 동일하게 사용한다.
- 함수로 묶는 STEP(예: STEP6)에서는 함수 이름과 입출력 형태를 명시하여, 이후 STEP에서 그 함수를 그대로 호출할 수 있게 한다.

## 7. 마지막 정리 셀

- "전체 흐름 정리" 표: STEP별 내용과 핵심 포인트를 한 줄씩 정리한다.
- ASCII 다이어그램으로 전체 파이프라인을 시각화한다 (`.원본 데이터 → STEP1 → STEP2 → ... → 최종 결과` 형태).
